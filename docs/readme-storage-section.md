### Фото клиентов

Фото клиента и документа лежат в приватном бакете `customer-photos`. Бакет создаётся миграцией, а не в Dashboard.

Доступ к файлам задают политики на `storage.objects`: загружать может активный сотрудник и только в папку с id существующего клиента, читать - активный сотрудник. Политик на UPDATE и DELETE нет: файлы неизменяемые, замена фото - это новый файл, старый остаётся как история.

В таблице хранится путь внутри бакета, не URL. Для показа сервер создаёт signed URL на 60 секунд сессионным клиентом пользователя, поэтому подпись получает только тот, кто и так проходит политику чтения.

Проверить, что бакет закрыт:

```bash
curl -i "$URL/storage/v1/object/public/customer-photos/<path>"

curl -i "$URL/storage/v1/object/customer-photos/<path>" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY"
```

Оба запроса файл не отдают.
